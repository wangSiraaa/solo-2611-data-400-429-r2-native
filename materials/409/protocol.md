# Durable subset

Pages are independent atomically replaced JSON files. A page contains page_id, page_lsn, and rows. Rows are fixed nonempty text keys, int64 values. Business ADD delta and persisted row values must fit int64; bool is not int. Internal UNDO inverse deltas and recovery arithmetic are mathematical integers (including +2^63 when undoing a legal -2^63 ADD), while every final persisted row value must remain int64. page_lsn is zero for the initial page and otherwise identifies its newest included physical log modification. Actual page IO fsyncs the file, replaces it, and fsyncs its directory. The controlled model injects failures between complete IO operations only, not torn writes or power loss inside fsync.

Journal.append assigns a global increasing positive LSN in volatile pending memory. Journal.force writes the whole pending prefix, flushes and os.fsyncs the real wal.jsonl. Journal.durable reads that file anew; it does not return a cached claim. Existing lines are complete, ordered, uncorrupted records, never recycled. Each record has kind, tx, lsn and prev_lsn. BEGIN has prev_lsn=0. ADD has page/key/delta. UNDO has page/key/delta plus undo_of and undo_next; its delta is the inverse of the referenced ADD. COMMIT is a durable success decision. ABORT follows a completed logical abort; its UNDO changes may still need redo on disk under NO-FORCE. Ended transactions release row write ownership, allowing a later transaction to use that same row. Recovery may append new record types or add image/progress metadata if needed, but existing delta records must remain interpretable.

The prototype recover replays only winner ADDs newer than a page_lsn. This handles the normal case but not uncommitted STEAL or durable-but-unflushed UNDOs. Full replay of non-idempotent deltas or repeated inverse deltas is not safe without an applied-state boundary. Do not assume the physical page is an empty database; untouched seed data and other committed keys must survive.

Scripts contain begin/add/commit/abort/flush/crash. crash emits the current audit and os._exit(73) without closing/flushing volatile state. The production target may add named recovery fault points; tests must observe an actual undo persistence boundary rather than only killing after redo. All old unsafe directories with a page_lsn beyond durable WAL must fail closed. There is one active engine/recovery coordinator; no business operation runs concurrently with recovery, no checkpoint/log truncation, no deletion/new row and no lock waiting. Target code may reorganize modules, but log durability, page IO, and recovery remain real observable responsibilities.

Initial existing row values may be arbitrary valid int64 values. The seed directory only creates example initial directories; it is not a retained runtime baseline. Recovery receives only the current pages and WAL, with no historical initial-page copy supplied.
