`python3 probe.py` executes the real shared scan and compares it with independent per-check filtering. Equal-population fusion works; the general planner and bounded-state implementation are now delivered:

- `compiler.py` — validates catalog + checks **before any source read** (unknown fields, NULL/non-leaf/type-incompatible literals, bad nulls policies, duplicate check_ids are rejected) and emits the shared plan: one scan per involved source, the columns each scan reads, and the responsibility boundary of every population and every reference target key domain. Predicates: `all/eq/in/is_null/and/or/not` with exact JSON types (`true != 1`, NULL only via `is_null`).
- `engine.py` — executes the plan: one real read per source, per-check population masks (each check keeps its own denominator, cardinality and error attribution), SQLite staging for duplicate groups and reference key domains. Assertions: `not_null`, `unique` (`nulls=equal|ignore`; a duplicate group of size k counts k rows), `reference` (independent `target_population`, typed composite keys, `nulls=ignore|reject`, duplicate target keys never amplify, each missing source row counts independently). Results carry `population_count`, `evaluated_count`, `violation_count`, `passed` and up to 3 smallest-row_id witnesses (unique adds a same-group partner, reference adds the missed typed composite key). Business violations still yield `status=complete, all_pass=false`; illegal config / corrupted source / interrupted read yield `incomplete` and unexecuted checks are never marked passed.
- `dq.py` — `compile` prints the shared plan, `run` executes it into `out/result.json`, `inspect` shows results plus the real `source.py` read counters, staging reads/writes, resident-row peak and the disclosed 4 MiB SQLite page cache.
- `selftest.py` — compares the shared executor against an independent per-check-scan oracle (cross-batch duplicates, two references sharing one target with different filters, duplicate target keys, all-ignored rows, empty sources, NULL/empty-string/true/1 typing, the 1000-row/3-population benchmark with decode ≤ 2000, config errors, corrupted sources, 3×3000-row scale with read-only sources).

Bounds: decoded rows + group payloads + pending witnesses stay within a 64-row resident budget (larger state spills to SQLite, whose page cache is capped at 4 MiB and disclosed separately); source decodes are counted per actual decode, staging reads/writes are reported separately.
